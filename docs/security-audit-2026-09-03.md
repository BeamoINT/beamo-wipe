# Security audit — 2026-09-03

Scope: all production Python under `src/beamo_wipe`, launchers and hosted scripts, Debian live-build inputs, kiosk boot path, release provenance, evidence/log handling, and the ISO/QEMU verification boundary. The audit used fake disks locally. Destructive checks are permitted only in the isolated x86_64 harness described in `docs/qemu-verify.md`.

## Dependency and image policy

- Production Python has no third-party runtime package dependency; build/test tools are not shipped.
- nwipe is pinned by both tag and full commit `6082bde060091e66365d852a1877f2ee80c67105`; the image gate checks the installed binary’s exact version and executes the bytes copied from the image.
- Debian repositories remain HTTPS plus Debian-signed metadata. The QEMU gate runs `debsecan --only-fixed` against the installed image database and stops on any available security fix.
- The build container is content-addressed. Updating its digest is an explicit reviewed change, not an implicit tag move.
- Hosted Python tools, Docker CLI, and the GCS publisher run on the same vulnerability-scanned Debian base with current Debian packages. The publisher uses Python's standard HTTPS library and workload metadata token; it does not ship the stale Cloud SDK/gsutil or Docker builder binaries found vulnerable during the audit, and it never logs the token.

## Residual boundaries and stop conditions

- The ISO is not Secure Boot signed and release checksums are not publisher signatures. An attacker able to replace both image and checksums can forge them. Do not claim tamper resistance or publish/promote an image without a separately authorized signing/release decision.
- Verification Cloud Builds remain ephemeral by default. Publication requires the explicit `_PUBLISH_RELEASE=true` post-QEMU gate, refuses skipped ISO/QEMU phases, uploads with generation-match-zero to a unique build path, verifies remote bytes, and writes `RELEASE_COMPLETE.txt` last.
- Root is still required to open raw block devices. The kiosk removes the normal login shell, but an attacker who can alter the unsigned boot chain or obtain kernel/root execution can bypass userspace gates. That threat requires a signed boot chain; it is not hidden by this application.
- `hdparm` is present for nwipe v0.42 HPA/DCO reads. The wrapper never invokes it and never emits security-erase flags. A root compromise remains outside the userspace containment guarantee above.
- QEMU validates virtio behavior, not physical controller firmware, USB bridges, RAID, remapped SSD areas, or formal sanitization standards. Any such claim remains prohibited.
- A failed local, hosted, ISO, Debian vulnerability, BIOS, UEFI, loop-identity, or shipped-engine check is stop-ship. No fallback is authorized.
