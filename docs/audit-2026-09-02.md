## 1. Safety invariants (applies to every row)

These invariants were established first and never relaxed — not for tests, not for convenience:

1. **Ambiguous identity → no targets.** `identify_boot_path()` → `None` ⇒ `parse_lsblk_json(require_boot=True)` ⇒ `DiscoveryResult(boot_identified=False, error=CANNOT_IDENTIFY, selectable=())`. Any duplicate `BEAMO_WIPE` label, unresolved `/dev/disk/by-label`, env/mount conflict, or duplicate UUID → `None`.
2. **All confirmation gates are mandatory, monotonic.** `assert_ready_to_wipe()` requires `owner_ok`, `is_wipeable_disk()`, `disk_identity()` unchanged, `token_matches()` (casefold trimmed `SAFE_TOKEN_RE`), `countdown_complete` (`COUNTDOWN_S=5.0`), `boot != target`, block-device exists (when not preview), `block_rdev` + `block_size_bytes` unchanged, `logfile_for()` under `/tmp/beamo-wipe` never on target. Order: `WHAT → OWNER (owner_ok) → PICK (selectable) → CONFIRM (token_ok) → METHOD → LAST_CHANCE (countdown) → WORKING → DONE`. No auto-start, no skip.
3. **Local preview/tests cannot touch real disks.** `./preview`, `./preview --web`, `--console`, `--lsblk-json` all set `BEAMO_WIPE_DRY_RUN=1` / `BEAMO_WIPE_DEMO=1` and use `DryRunRunner` (validates `build_nwipe_argv` but never `Popen`). `discover(lsblk_payload=…)` never calls `run_lsblk()`/`read_mount_sources()` when payload injected. `conftest.py` forces `BEAMO_WIPE_DRY_RUN=1` for pytest. `NwipeRunner.start()` calls `require_real_live_for_nwipe()` → `SafetyError` in preview/dry-run.
4. **Success requires verified zero exit.** `evaluate_nwipe_completion()` → `ok=True` only if `exit_code==0` **and** (`| Erased |` row with device mention **or** 100% on last pass of last round) **and** none of busy/abort/open-fail/geometry/failure markers. `format_progress_percent()` never renders `100%` before `100.0`. Evidence `outcome` never upgrades `failed` → `verified`/`completed`.
5. **Logs never go to the target.** `default_log_dir()` creates `0700` under `/tmp` on same dev as `/tmp`, refuses symlink, `st_uid` match, `_is_under(/tmp)` check. `assert_log_not_on_target()` checks `FORBIDDEN_LOG_ROOTS`, `realpath(target)` prefix, mountinfo source device equality (via `st_rdev` or partition inference), `O_NOFOLLOW|O_CREAT|O_TRUNC 0o600` in `truncate_log_file()` and evidence atomic writes. `is_preview_env()` skips mountinfo check where `/proc` absent on macOS (correct fail-open in preview, fail-closed on live).

Any change to these is a `safety:` commit with a test. This audit verified them line-by-line.

## 3. Verified findings (new, deduped against BF-001..009)

### BF-010 — `Wizard.confirm_erase` unhandled rediscover exceptions → crash instead of fail-closed (MEDIUM, safety-adjacent)

- **Evidence (repro):**
  ```python
  # BEAMO_WIPE_DRY_RUN=1, Wizard(dry_run=False, rediscover=lambda: raise CalledProcessError(1,'lsblk'))
  # Drive to LAST_CHANCE, set _erase_until=0, call confirm_erase()
  # Before fix: raises subprocess.CalledProcessError (uncaught), traceback, no friendly error
  # After fix: screen stays LAST_CHANCE, error=="Could not re-read disks: Command 'lsblk' returned non-zero exit status 1.", started==False
  ```
  Fixture: `CalledProcessError(1,'lsblk')` and `TimeoutExpired('lsblk',15)`. Both crashed pre-fix. `OSError`/`ValueError` were already handled and correctly showed the error.
- **Severity:** Medium. Blast radius: live USB only (`dry_run` path skips rediscover). If `lsblk`/`findmnt` transiently fails between `LAST_CHANCE` and `Erase`, wizard would traceback instead of showing “Could not re-read disks” and blocking the wipe. No destructive target exposed (crash occurs before `assert_ready_to_wipe`), so fail-closed in practice but via unhandled exception, not user-visible refusal.
- **Affected files:** `src/beamo_wipe/wizard.py:309-313` (`confirm_erase` except), `packaging/live/.../beamo_wipe/wizard.py` (staged copy).
- **Root cause:** Except clause only listed `OSError, ValueError`; `discover()` itself catches `CalledProcessError, TimeoutExpired, JSONDecodeError, TypeError, AttributeError` and returns `CANNOT_IDENTIFY`, but the `rediscover` callable is `discover` (no args) which on failure raises `CalledProcessError` before returning — `discover()`’s outer handler does catch it and returns fail-closed, yet the test used a throwing `rediscover` lambda. More generally, a future rediscover implementation could raise those. Widening the handler to the full `discover()` exception family plus a final `Exception` guard makes `confirm_erase` fail-closed with a message for any re-read failure.
- **Acceptance criteria:** `confirm_erase` catches `OSError, ValueError, CalledProcessError, TimeoutExpired, JSONDecodeError, TypeError, AttributeError` and a final `Exception`, sets `self.error` to `Could not re-read disks: …`, stays on `LAST_CHANCE`, `runner.start` not called. New or existing test `test_wizard_rediscover_failure_is_fail_closed` passes. `python3 -m pytest tests/test_wizard_flow.py tests/test_confirmation_gates.py -q` green.

### BF-011 — `THIRD_PARTY.md` claims a Debian `nwipe` fallback that the build does not have (LOW, docs)

- **Evidence:** `THIRD_PARTY.md:16-18` (pre-fix): “If the build cannot clone GitHub, it may fall back to the Debian `nwipe` package …” `packaging/live/config/hooks/normal/0500-build-nwipe.hook.chroot:2` says “No distro fallback — bookworm's nwipe is not 0.42.” and on clone failure after 5 retries prints `ERROR: git clone nwipe failed after 5 attempts` and `exit 1`. No `apt-get install nwipe` exists (and `tests/test_live_image.py::test_nwipe_hook_fails_closed…` asserts absence). The doc misleads an operator into expecting an ISO with a wrong nwipe version.
- **Severity:** Low (docs). Blast radius: operator confusion; no safety bypass (build fails closed correctly).
- **Affected files:** `THIRD_PARTY.md:16-18`.
- **Root cause:** Doc not updated when hook was hardened to pinned-commit-only (commit `2a1fd31`, `140`-line hook). Stale fallback language remained.
- **Acceptance criteria:** `THIRD_PARTY.md` says: no fallback, 5 retries then fail, hook refuses ISO if `NWIPE_VERSION` ≠ `0.42`, records version in `/usr/share/doc/beamo-wipe/NWIPE_VERSION`. `grep -q "apt-get install.*nwipe" packaging/live/config/hooks/normal/0500-build-nwipe.hook.chroot` fails (0 hits). `grep -q "No distro fallback" packaging/live/config/hooks/normal/0500-build-nwipe.hook.chroot` succeeds and `grep -q "No fallback.*Debian" THIRD_PARTY.md` indicates alignment.

### BF-012 — CI lint gate is non-blocking (`|| true`) so unused-import regressions do not gate PRs (LOW, CI)

- **Evidence:** `.github/workflows/ci.yml: lint` job: `python -m ruff check src/beamo_wipe tests || true`, `python -m mypy --ignore-missing-imports src/beamo_wipe || true`, and `grep TODO … | grep -v …` only warns. Running `python3 -m ruff check src/beamo_wipe tests` without `|| true` currently reports **31 errors** (e.g., `tests/test_boot_exclusion_fails_closed.py:24 F401 parse_lsblk_json unused`, `tests/test_confirmation_gates.py:18 F401 os unused`, etc.). Those do not block `test`/`iso` (lint `needs` but never fails). Intentionally per `docs/ci.md` “non-blocking best-effort”, but the *safety* lint (e.g., `assert_boot_excluded` dead code) should gate.
- **Severity:** Low. Blast radius: code hygiene drift; tests still gate, but a safety-adjacent dead-code removal could hide behind lint-as-warning.
- **Affected files:** `.github/workflows/ci.yml:22-31`, `pyproject.toml` absent `[tool.ruff]`, `tests/*.py` (31 lints).
- **Root cause:** Org originally set lint non-blocking to avoid blocking PRs on style; ruff/mypy were added as informational. Follow-up is to make `ruff check` (without `--fix`) blocking and keep `mypy` informational, or at least add a dedicated `safety-lint` job that greps for `TODO` without issue link as blocking.
- **Acceptance criteria:** Either `ci.yml` changes to `run: python -m ruff check src/beamo_wipe tests` (no `|| true`) **or** a new blocking job is documented as intentional non-blocking with rationale in `docs/ci.md` § Failure triage. ### BF-013 — Release instruction `sha256sum -c dist/beamo-wipe-*.iso.sha256` from repo root fails due to bare filename in sidecar (LOW, docs)

- **Evidence:** `dist/beamo-wipe-0.1.0-amd64.iso.sha256` contains `8a531d…  beamo-wipe-0.1.0-amd64.iso` (bare). `sha256sum -c dist/beamo-wipe-0.1.0-amd64.iso.sha256` from repo root says `beamo-wipe-0.1.0-amd64.iso: No such file or directory` because it looks in cwd. `dist/SHA256SUMS` correctly requires `cd dist && sha256sum -c SHA256SUMS`. `docs/release-verification.md` documents both forms, but `scripts/generate-release-manifest.sh` and `ci.yml` use `(cd dist && sha256sum -c …)` while `README.md` example shows bare. Verified with `python3 -c "import pathlib; … verify_manifest"` and `sha256sum` repro (see §7).
- **Severity:** Low. Blast radius: consumer confusion, not safety (manifest `_manifest_sha256` still verifiable via `verify_manifest`).
- **Affected files:** `dist/beamo-wipe-0.1.0-amd64.iso.sha256` format (intentional bare), `docs/release-verification.md:26` (already documents `(cd dist && …)`), `README.md`flash section does not mention verification.
- **Root cause:** Sidecar is written by `sha256sum beamo-wipe-*.iso > beamo-wipe-*.iso.sha256` (bare), correct for `cd dist` use, but repo-root `sha256sum -c dist/…` needs `dist/` prefix or `sha256sum dist/iso` form. No code fix needed; doc clarification.
- **Acceptance criteria:** `docs/release-verification.md` § Consumer verification shows both `(cd dist && sha256sum -c SHA256SUMS)` and `sha256sum dist/beamo-wipe-*.iso` (full path) forms; `scripts/generate-release-manifest.sh` uses `cd dist` for verification (already). No change to sidecar format.

## 11. Remaining risks / unsupported hardware (honest, not hidden)

Same as `docs/compatibility-matrix.md` §14 + `docs/storage-and-controller-limits.md` §3..7, plus new BF-012/013:

- **APFS/BitLocker/SED/OPAL/T2** — not unlocked, not wiped; appear as raw block or not at all. No password reset, SAM edits, or Secure Boot circumvention (safety boundary). → Vendor tool or destruction.
- **NVMe/SATA sanitize not in image** — wrapper only does overwrite (`nwipe`); `nvme-cli`/`hdparm` sanitize not shipped (`beamo.list.chroot` minimal). For certified erase, use vendor tool per model (see `docs/storage-and-controller-limits.md` §6) or destroy.
- **RAID / RST / mdadm / LVM / nbd/iscsi/fc/nvmeof** — hidden via `REMOTE_BUS_TOKENS` + `WHOLE_DISK_RE`; hardware RAID virtual disk not claimed.
- **HPA/DCO / hidden NVMe namespaces / OP area** — LBA overwrite does not cover them; `smartctl` `Reallocated_Sector_Ct`/`hdparm -N` not probed by wizard. → Destruction.
- **SSD controller dependence** — wear leveling/trim/OP (same-disk, see `SSD_FOOTER` on pick + evidence `warnings[]`). Overwrite is not a certificate.
- **USB-SATA bridges** — `tran sata` for USB stick → label fallback fails closed; only mounts identify correctly (BM-05/06). Documented degraded.
- **eMMC only / `mmcblk0boot0`** — 4 MiB boot/rpmb hidden; `PICK_EMPTY` correctly shown (ST-09/DISP-06). Do not promote `boot0` to target.
- **Firmware:** Secure Boot unsigned → fails to boot (correct, no circumvention). Chromebooks, Apple Silicon, RAID controllers remain unsupported per `docs/claims.md` forbidden list.
- **CI lint non-blocking (BF-012):** 27 `ruff` lints remain informational; a future safety dead-code could hide behind them until blocking. Tracked as BF-012.
- **Sidecar bare filename (BF-013):** Consumer must run verification from `dist/` or use full path; not a safety risk, but doc clarifies.

No new NVMe/SD controller lab work was done in this audit (requires x86_64 KVM + real NVMe per `docs/qemu-verify.md` + `docs/storage-and-controller-limits.md` §3 table “Not reproduced on real NVMe/SD controller in this checkout”).
