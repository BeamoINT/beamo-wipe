# Beamo Wipe bug audit — 2026-09-24

Base: `34b4ffd` on `safety/windows-gpt-contents`. This pass used fake disks,
synthetic nwipe logs, and disposable report bundles. No physical disk was
erased, and release publication remained disabled.

## Reproduced and fixed

1. A completed nwipe log longer than the 1 MiB tail could hide an earlier
   target failure while leaving a later `Erased` row visible. The runner now
   scans the complete log with bounded memory and checks its file identity
   across the scan. Oversized or changing evidence remains indeterminate.
   Long successful logs still reach their real completion result. Synthetic
   early-failure and long-success regressions were red before the change and
   green afterward.
2. The hosted QEMU report verifier accepted a recorded nwipe command with
   `--force`, a second target, or a second boot exclusion because it only
   searched for required flags. It now requires the exact production argument
   list for one target, the recorded boot device, and the tmpfs log path.
   Three disposable report regressions were red before the change and green
   afterward.
3. A report summary crashed on a list-valued build status or clock source,
   or on an integer duration too large for a float. TXT and HTML generation
   now show `unavailable` for those malformed fields. All three cases were
   reproduced before the fix.
4. A release gate receipt could claim `pass` when every check was skipped,
   or claim `skip` while recording passing checks. The receipt builder now
   rejects both states. Focused regressions were red before the fix.

## Follow-up pass on the same checkout

   the shipped USB and storage device set. Red-to-green fixtures cover the
   previously accepted commands.

   and issue passing counts. It now rejects nested or hidden tests; a failed
   suite fixture was red before the fix.
8. The dpkg status parser could silently omit an installed package when a
   duplicate or continued `Status` field changed its meaning. It now rejects
   those malformed records and still accepts valid multiline descriptions.
   Both malformed cases were reproduced before the fix.
9. Whole-log nwipe completion scanning did not feed the report's media checks.
   An early hidden-capacity warning could be lost beyond the 1 MiB exported
   tail, and a contradictory later `No hidden sectors` line could make the
   check appear to pass. Terminal reports now assess a bounded projection of
   the entire log, while preserving an exact hashed tail for export. Red
   examples and pinned-log fixture comparisons pass.
