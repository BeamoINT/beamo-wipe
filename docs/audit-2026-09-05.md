# Beamo Wipe audit — 2026-09-05

Status: initial audit and QEMU follow-up findings; validation history below.
Base commit: `ce6798bbd86caa591e0ea0416ca84392e143a8d8`.

Five bounded reviews covered discovery/exclusion, runner, wizard, evidence/recovery,
and boot/build. Each finding was reproduced independently before its fix. All

No physical disk was erased or passed through to a VM. No release was performed.

## Confirmed defects and minimal fixes

| Defect | Before-fix proof | Change |
| --- | --- | --- |
| Build errors reported as success | `run_logged` returned 0 for inert commands exiting 1, 37, 126, 127, 130, and 143 | Capture the command status inside the failed `if` branch |
| Unknown live source ignored | Known `/dev/sdb` plus unresolved UUID still offered targets | Require every observed live source to resolve |
| Mounted physical ancestor offered | Flat `sda → sda1 → mounted dm-0` left `sda` selectable | Follow mounted ancestry to physical parents; reject unresolved/cyclic ancestry |
| Malformed mount data treated as empty | Production metadata containing `[False]` or `[0]` left the disk selectable | Require mount array entries to be strings or null |
| Remote transports offered in picker | TCP/RDMA NVMe transports were selectable, although the final kernel gate refused them | Exclude the known remote transports during selection |
| Malformed progress treated as completion | Exit 0 with a truncated or malformed pass clause produced success | Require a complete counter boundary before accepting progress |
| Old cancellation discarded a retry | Event-controlled cancellation returned after a new fake process started and cleared it | Check process identity before applying cancellation results |
| Completion released a newer run's lock | Paused completion allowed retry, then released the retry's actual temporary-file flock | Retire the process and its lock under the same mutex |
| Nonregular logs stalled readers | Five readers blocked opening same-owner temporary FIFOs before checking file type | Open nonblocking, preserving existing regular-file, ownership, and size checks |
| Console EOF left an erase running | Closed input repeatedly polled the fake active wipe | Route EOF through existing system-interruption and report-retention handling |

## Follow-up: separate findmnt records

A synthetic reproduction against `5c348d2` proved another parsing defect:
`findmnt` stdout `/dev/sr0\n/dev/sr0\n` was combined into one invalid source,
even when mountinfo independently identified `/dev/sr0`. The strict boot-source
gate correctly refused that invented source. The reproduction returned one
failure and one passing single-row control before any parser change.

`read_mount_sources` now parses separate nonempty records and deduplicates
normalized sources. Unknown sources and conflicting physical owners remain
blocking. Nine follow-up tests cover duplicate rows, multiple owners, unknown
sources, blank records, line endings, and identifier-free failure markers.

The original QEMU failure could not yet be attributed to this parser defect
from its existing logs. Fixed diagnostic markers were added for source shape
and the allowlisted discovery error code. Successful and failed QEMU probes
report only exact recognized marker counts; raw device identifiers and logs
remain private. Twenty-seven fake-UI and fake-serial regressions failed before
that visibility change and passed afterward. These markers make subsequent
hosted evidence available without changing the boot-exclusion decision.

The next full hosted gate must validate the follow-up commit before pushing.
The initial failed run above is retained as a historical receipt, not a current
claim that the revised parser works in the guest.
