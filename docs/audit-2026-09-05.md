## Confirmed defects and minimal fixes

| Defect | Before-fix proof | Change |
| --- | --- | --- |
| Build errors reported as success | `run_logged` returned 0 for inert commands exiting 1, 37, 126, 127, 130, and 143 | Capture the command status inside the failed `if` branch |
| Unknown live source ignored | Known `/dev/sdb` plus unresolved UUID still offered targets | Require every observed live source to resolve |
| Mounted physical ancestor offered | Flat `sda → sda1 → mounted dm-0` left `sda` selectable | Follow mounted ancestry to physical parents; reject unresolved/cyclic ancestry |
| Malformed mount data treated as empty | Production metadata containing `[False]` or `[0]` left the disk selectable | Require mount array entries to be strings or null |
| Remote transports offered in picker | TCP/RDMA NVMe transports were selectable, although the final kernel gate refused them | Exclude the known remote transports during selection |
| Malformed progress treated as completion | Exit 0 with a truncated or malformed pass clause produced success | Require a complete counter boundary before accepting progress |
| Old cancellation discarded a retry | Event-controlled cancellation returned after a new fake process started and cleared it | Check process identity before applying cancellation results |
| Completion released a newer run's lock | Paused completion allowed retry, then released the retry's actual temporary-file flock | Retire the process and its lock under the same mutex |
| Nonregular logs stalled readers | Five readers blocked opening same-owner temporary FIFOs before checking file type | Open nonblocking, preserving existing regular-file, ownership, and size checks |
| Console EOF left an erase running | Closed input repeatedly polled the fake active wipe | Route EOF through existing system-interruption and report-retention handling |

## Remaining risk and scope

- Linux Tk/GTK accessibility and artifact-dependent skipped tests remain to be
  exercised by the hosted gate. Local passing tests do not establish those results.
- No current amd64 ISO, BIOS/UEFI boot, shipped-engine wipe, or report-USB VM
  receipt was produced. The inspected QEMU harness uses private file-backed
  targets, verifies loop ownership, and has no host-disk passthrough. BIOS tests
  exercise the wizard/report flow; the UEFI probe covers startup.
- Physical SATA, NVMe, USB bridges/controllers, and Secure Boot were not tested.
  Synthetic fixtures and virtual devices do not establish hardware compatibility.
- Unknown loop-backed live sources now stop safely even if another source
  resolves. A loop merely present in the inventory does not block known boot
  ownership; no loop owner is inferred.
- Current report export and shutdown-retention UI paths are present. Evidence
  and preferences remain volatile until a verified export; power-loss durability
  was not established by these local checks.
- The commit-order dependency is resolved by explicit authorization; hosted
  validation remains pending. This is not a claim that all defects have been
  found or that the patch is production-ready.
