## Confirmed fixes

1. **Rejected lock file closed twice.** `_acquire_wipe_lock()` closed an invalid file descriptor before raising, then closed it again in the exception handler. The handler now owns the single close. A fake-descriptor regression demonstrated two closes before the fix and one afterward.
2. **Process-status failures invisible to the operator.** `NwipeRunner.poll()` logged a failed process-status read and returned `None`, which the wizard interpreted as an ordinary running process. It now raises a specific `ProcessStatusError` for the current process so the wizard displays its existing warning. A concurrently completed operation retains its terminal result. Cancellation handles this specific status error and still requires confirmed process exit and successful cleanup.
3. **Obsolete process warnings persisted.** A warning about uncertain process status survived a later successful status read, and failed-stop warnings could remain on the completed result screen. Successful polling clears only its own status warning; confirmed terminal transitions clear obsolete operation errors. Evidence and export warnings retain their separate state.

Nine new regression cases cover descriptor lifetime, both status exception types, warning recovery while running and after completion, unrelated warnings, concurrent completion, cancellation during unavailable status, and completion after an unsuccessful stop. Existing status-error expectations were updated to require a visible failure.
