## Confirmed defects and minimal fixes

1. **Conflicting duplicate device observations could evade exclusion.** A mounted or read-only `/dev/sda` row was filtered away while a second writable row remained selectable and passed `assert_disk_identity`. Compare canonical-path observations before eligibility filtering; conflicting records now fail closed. Preserve the existing rule that even identical duplicate targets remain ambiguous and cannot pass final identity validation. An initial coalescing proposal failed an existing safety test and was corrected, without weakening that test. New tests cover both orders, read-only/mounted/remote/zero-capacity/identity conflicts, aliases, boot records, normal input, and recovery on refresh.
2. **Separate approved log subdirectories defeated global wipe locking.** Two runners could acquire different `wipe.lock` files before either process appeared in `/proc`. All runners now acquire the same validated log-root lock. Fake subprocess and threaded tests cover the pre-exec window, duplicate starts, preservation of the second log, cancellation, and retry. Two existing direct-lock tests now use the canonical root fixture.
3. **Permanent console input failures left erasure running without usable cancellation input.** `select`/`readline` permission, closed-input, or descriptor failures were swallowed repeatedly. Route permanent errors into the existing EOF cancellation and report-preserving recovery path. `InterruptedError` still retries. Tests verify report intent, terminal states, and refusal to claim completion if stopping cannot be confirmed.
4. **Duplicate diagnostic JSON keys could conceal private bytes during validation.** JSON decoding retained only the final value, but export retained the original raw bytes. Reject duplicate keys recursively before validation/export. Tests cover root and nested keys, both export boundaries, and normal bundle readback.
5. **Hardlinked diagnostic logs modified unrelated files.** Logging changed the linked file from mode 0644 to 0600 and appended diagnostics. Reject multiple links before chmod/write. A temporary-file regression verifies refusal and preservation of both bytes and mode.

All reproductions used synthetic discovery payloads, fake engines, and temporary files. No real disk was opened, erased, passed to QEMU, or used as a fixture.
