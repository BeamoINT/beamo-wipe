## Confirmed fixes

1. **Storage error paths leaked descriptors.** Recovery-file and report-preference directory metadata checks did not close their newly opened descriptors when `fstat` failed. Evidence and preference writers could also skip directory closure when temporary-file cleanup failed. These paths now close the owned descriptors even when validation or cleanup raises.
2. **The evidence writer retried a failed close.** A close failure reached cleanup before the descriptor sentinel was cleared. Retrying that descriptor number is unsafe when the first close released it. The writer now relinquishes ownership before closing and does not publish evidence after a failed close.
3. **Short reads rejected valid recovery state.** The recovery journal and saved report preference assumed one read returned the whole record. Both now accumulate bounded reads through EOF. Existing ownership, permission, link, format, and size checks remain enforced; invalid records still fail closed.

Nine new cases failed before the fixes. Twelve regression cases now cover those failures plus exact journal-size boundaries and bounded rejection of trailing preference data. They use ordinary temporary files or mocked syscalls, never real block devices.
