## Confirmed fixes

1. **Report read failures escaped the UI action.** An I/O or permission error while reading saved evidence propagated out of both synchronous and background export entry points. The controller now reports a fixed, private-data-free error, keeps the terminal result, and permits an explicit retry. No exporter starts while evidence cannot be read.
2. **Worker construction failure stranded the export claim.** The controller marked a report as saving before constructing its thread, but only thread startup was inside the error handler. Construction failure left the export busy and shutdown blocked. Construction and startup now share the existing recovery handler, which releases the claim and restores retry and guarded shutdown.
3. **Recovered diagnostic README misdescribed the result.** For `recovery_indeterminate`, JSON correctly said the previous result was unavailable, but the exported README said the wipe could not start. The bundle now uses the validated report title, preserving uncertainty about the previous operation.

Eight new regression cases exercise both export entry points with I/O and permission errors, worker construction and startup failures, and ordinary versus recovered diagnostic titles. The new failure cases were observed before the corresponding fixes. They verify successful retry, preserved results, no premature exporter calls, privacy of error messages, and shutdown protection.
